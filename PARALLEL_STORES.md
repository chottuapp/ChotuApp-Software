# Parallel Stores update

The existing Fetch Selected / New Fresh Run / Continue Saved Run buttons now schedule up to two different website sources in separate Python processes. Each process has independent extraction globals, HTTP sessions, per-store SQLite response caches, workbook construction and output staging. The existing extraction, price/variant/category/description/image checks and source pacing/cooldown profiles are retained.

The parent alone owns the Saved Runs lease and queue database. It routes progress and results by store index, validates newly saved workbooks, updates the matching queue entry and announces each completed file immediately. Completed stores are skipped on continuation. Cached successful HTTP responses remain scoped to the original run and store. A new fresh run still starts a new checkpoint identity. A child crash or a website cooldown does not stop unrelated stores.

The same website (including www aliases, and Farda root/shop aliases) never runs twice concurrently. Duplicate store names which would map to the same output filename are rejected rather than overwriting another store. Each child caps healthy HTTP preloading at two workers and preserves stricter single-worker recovery settings. No learned source pacing or Retry-After is reset. The browser dependency and Czone-specific parsing rules are unchanged.

Pause controls every active child at the next safe wait/checkpoint. Closing requests cancellation and retains successfully committed request responses; unfinished work is retried using Continue Saved Run. Active export files are staged by the existing export wrapper. The parent verifies that the output workbook is new, readable and has product rows before marking a store done. Stale files are not accepted as new results. All selected stores retain their saved queue positions.

Install only after closing the app: `py install_parallel_stores.py`. The installer requires the existing Saved Runs and Fast Fetch hooks, backs up the current source, adds one startup hook and two modules, and refuses to run while a Saved Runs lease is held. It does not replace any extraction-support module, preferences, template, queue state or output workbook. No new dependency or browser download is required.

After restart use Continue Saved Run for interrupted work. Use New Fresh Run for a new selection. The interface layout and buttons are retained. Look for `PARALLEL STORES: up to 2 different websites together` and store-prefixed logs.

Validation: 12 new process/scheduler/installer/GUI integration tests passed, including actual subprocess overlap, same-domain serialization, bounded concurrency, isolated files, cooldown independence, child crashes, stale-output rejection, pause/stop/continuation, duplicate output-name protection and existing button states. Seven existing Saved Runs/GUI tests and five existing Fast Fetch tests passed, including full workbook-cell and endpoint equivalence under the existing extraction engine. These local tests use controlled fixtures; Windows live-store runtime and speed depend on source response times and rate limits. Running two stores together can reduce batch elapsed time; it does not guarantee a specific per-store speedup or eliminate 429 responses.
