# Cloud Rule 804 → Google Drive

The authorized fresh batch 39450710625 (26 stores, excluding LAAM, Khaadi and Sapphire) can upload without a Windows PC. `cloud-drive-sync.yml` checks approximately every five minutes, on fetch completion, and on manual dispatch. GitHub scheduling can be delayed. Existing already-running fetch jobs need not be restarted.

Run `catalog-tools/enable_cloud_drive_windows.py` once on the existing authorized Windows machine. It captures only `rclone config show chotudrive`, validates the single Google Drive remote and sends it on stdin to `gh secret set CHOTU_DRIVE_RCLONE_CONFIG`. It does not print credentials, put them in the repository, upload other remotes or change local files. Do not paste tokens or rclone config into chat. The first cloud upload must succeed before considering cloud Drive access verified.

Only `chotuapp-rule804-files` artifacts are accepted. Every workbook must have Rule 804 metadata, pipeline/source hashes, the expected store/file identity and matching bytes. Files that fail processing are held upstream. Raw Excel artifacts are never uploaded. The automated Rule 804 pass is bounded; category/website-order and other review warnings remain explicit. It is not a human editorial review.

For newly processed/changed workbooks, the destination is `chotudrive:ChotuApp DD-MM-YYYY Fresh`, using Pakistan time at upload. Folders are created by Drive when the first verified workbook is copied. Unchanged old workbooks are not copied into each new date as freshly fetched data. Prior dated folders and unrelated files are preserved; copy/check do not delete them. The uploader publishes credential-free checksum records, per-folder results, warnings and source run IDs on `drive-sync-reports`. Entries are marked verified only after rclone checksum checks succeed. Interrupted uploads are retried; names are stable and copies are idempotent.

This does not schedule a new catalog fetch every day. It uploads the current authorized batch as results become available. Google Drive credentials are used only in a temporary 0600 config on the cloud runner. A missing/revoked secret, GitHub outage/limits, expired artifacts or Drive failures prevent confirmation and require repair; no false success is recorded. Khaadi's separate local fetch still needs the user's PC because its Pakistan pages redirect from cloud regions.
